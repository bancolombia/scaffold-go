# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities in public issues, discussions, or pull requests. 

We prefer private disclosure via GitHub Security Advisories before public disclosure. Use GitHub's private reporting form for this repository:

[Report a vulnerability](https://github.com/bancolombia/scaffold-go/security/advisories/new)

Include as much of the following as you can:

- The affected `scaffold-go` version or commit.
- The operating system and Go version, if relevant.
- A description of the vulnerability and its potential impact.
- Clear reproduction steps or a proof of concept, using only systems and data you are authorized to test.
- Any practical mitigation, if known.

Do not include real credentials, personal data, or other secrets in a report. Avoid actions that could disrupt services, destroy data, or access information belonging to others.

If GitHub private vulnerability reporting is unavailable, open an issue asking the maintainers for a private contact method. Do not include vulnerability details, reproduction steps, or proof-of-concept code in that issue.

## What to expect

The maintainers will acknowledge reports as soon as practical, investigate the reported impact, and coordinate with the reporter on a fix and disclosure timeline. Please allow time for affected users to update before sharing vulnerability details publicly. We will credit reporters in an advisory when they wish to be credited.

This process covers the `scaffold-go` CLI and code or templates maintained in this repository. It does not provide a security review of third-party dependencies or of projects generated and subsequently modified by users.
